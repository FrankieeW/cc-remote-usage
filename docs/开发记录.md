# 开发记录：ccr（cc-remote-usage）

把跑在服务器上的 Codex / Claude Code agent 的**今日用量**汇进 CC Switch 看板的完整来龙去脉。
记录的是「为什么这么做」和踩过的坑，代码结构见 README / AGENTS.md。

## 1. 需求

本机 CC Switch 的「用量」看板只统计本机 agent 的消耗；VPS 上跑的 agent（netcup、nuyek-yeats
等）看不到。目标是：**同一个看板里能看到所有服务器的今日/近 N 天用量**。

最早的误解是「要同步余额（额度）」，实测后发现用户要的是**每日消耗**，这是两条完全不同的数据通路。

## 2. 调研：CC Switch 的用量到底怎么来的

在 `~/.cc-switch/cc-switch.db` 里读出来的事实（CC Switch 4.0.16，Fleet 变体）：

| 表 | 字段/取值 | 含义 |
|---|---|---|
| `proxy_request_logs` | `data_source='proxy'` | 本机代理逐请求记账 |
| `proxy_request_logs` | `data_source='codex_session' / 'claude_session' / 'grok_session' / 'pi_session' / 'mcode_session'` | **从会话日志解析出来的用量** |
| `usage_daily_rollups` | `(date, app_type, provider_id, model, …)` | 按天汇总表 |
| `session_log_sync` | `file_path` 主键 + `last_byte_offset` | 增量游标，天然幂等 |
| `session_usage_dedup` | `(data_source, request_id)` | 会话用量去重 |

关键结论：

1. **「用量」= 会话日志解析**，入口是 `cc-switch sessions sync-usage`。
2. 扫描根受环境变量控制：`CODEX_HOME`（→ `$CODEX_HOME/sessions`、`$CODEX_HOME/archived_sessions`）、
   `CLAUDE_CONFIG_DIR`（→ `$CLAUDE_CONFIG_DIR/projects`）。
   ⇒ **把目录作用域化，就能只扫某台服务器的镜像目录**，这是整个方案的地基。
3. `session_log_sync` 按文件字节偏移去重，所以重复导入是安全的。
4. 会话解析出的用量统一归到伪供应商 `_codex_session` / `_session`，**不区分是哪台服务器**。
   ⇒ 按服务器拆分只能自己算（`ccr report`）。
5. `usage_daily_rollups` 在实测环境里 max(date) 停在旧日期，看板的近实时数据来自
   `proxy_request_logs`，别拿 rollups 当唯一事实源。

### 顺带查清的两件事

- **「额度」不是「用量」**：额度来自供应商的 `usage_script`（每个 provider 存
  `meta.usage_script` 的 JS，如 new-api 的 `/api/user/self`、MiniMax 的
  `/v1/api/openplatform/coding_plan/remains`），由 `cc-switch provider quota <id>` 触发。
- **服务器 agent 用的账号可能已经和本机同源**：逐台比对 key 指纹后发现 netcup 的 Claude
  用的是和本机 DeepSeek 相同的 key、frankie-vps 用同一个 MiniMax `sk-cp-` token、三台 Codex
  共用同一个 ChatGPT account（`044aff82…`）——这些本来就已经统一，只有 nuyek-yeats 是独立来源。

## 3. 方案演进

| 版本 | 形态 | 结论 |
|---|---|---|
| v0 | `bash` 同步脚本 + Python 报告 + launchd | 验证可行（净cup 首轮导入 5092 条），但交互/状态/报错太糙 |
| v1 | Rust CLI（本仓库） | 自动发现 + 交互多选 + 增量 + 报告 + daemon |
| v2 | 加失败退避 | 死机器不再每轮赔超时 |

## 4. 技术选型与坑

1. **服务器普遍没装 rsync**（netcup 直接 `command not found`）⇒ 用 tar 流式：
   ```sh
   ssh host 'cd ~/.codex/sessions && find . -type f -name "*.jsonl" -newermt @N | tar -czf - -T -' \
     | tar xzf - -C <本地镜像目录>
   ```
   GNU tar 在文件列表为空时会产出**合法的空归档**并返回 0，所以管道不会报错——这点很重要，
   否则「今天没有新日志」会被当成失败。
2. **BSD find 不认 `-newermt @epoch`** ⇒ 远端先跑 `find . -maxdepth 0 -newermt '@0'`
   探测，失败就退回 `-mmin -N`。
3. **增量语义**：`find -newermt @<上次成功同步的 epoch>`；`last_epoch` **只在成功时推进**，
   失败不推进，避免漏数据。
4. **并发探测**：`std::thread::scope` + `AtomicUsize` 任务队列，固定 8 并发。12 台主机从
   串行的 ~40s 降到 7s。
5. **超时噪音**：完全不可达的主机每轮固定赔 5s 连接超时 ⇒ 指数退避（15m→30m→1h→2h→4h→6h，
   上限可配）。冷却中的主机在探测阶段就被剔除，连 SSH 连接都不建。
6. **Fleet 主机发现会混进 git 远端**：`cc-fleet hosts` 复用 Codex App 的 SSH 列表，里面包含
   `github.com` 的 git alias（`user git`）。必须先解析 `~/.ssh/config` 的
   `HostName`/`User`，反查过滤掉这些。
7. **计价口径**：读 CC Switch 自己的 `model-pricing.json`（不是 SQLite），模型名大小写不敏感、
   支持前缀匹配（带日期后缀的模型名），取最长命中；`codex-auto-review` 这类没有定价的记 `n/a`。
8. **时区**：会话 JSONL 里的时间戳是 UTC，`report` 转本地时区后归日；晚上 23:40 的会话会算到
   「昨天」，这是正确但容易误判的行为（本地日期 00:00 起算）。
9. **离线构建**：本机访问 crates.io 403，`cargo build --offline` 靠本地 registry 缓存
   （clap 4.6.7 / serde_json / dialoguer / chrono 都有），30 秒出 1.1MB 二进制。
10. **不要直接写 CC Switch 数据库**：所有数据都通过它自己的 CLI 落库，保持它的事务/去重逻辑。

## 5. 验证方法（可复用）

```sh
# 1) 看板数据源里各来源的条数
sqlite3 ~/.cc-switch/cc-switch.db \
  "select data_source, count(*) from proxy_request_logs group by 1 order by 2 desc"

# 2) 单台导入是否生效（作用域化环境变量）
CODEX_HOME=~/.cc-switch/remote-usage/<host>/codex \
CLAUDE_CONFIG_DIR=~/.cc-switch/remote-usage/<host>/claude \
  cc-switch sessions sync-usage --all --json

# 3) 自己的报告与看板数字对照
ccr report --days 2

# 4) 验证幂等：连跑两次，第二轮 imported 应为 0
ccr sync <host>
```

实测基线（2026-10-21）：

- netcup：3 天 41 个 Codex rollout ≈ 228MB 压缩后，首次 3 分钟；增量 4.2 秒
- nuyek-yeats：2 天 17 个文件 56MB，首次 8 秒导入 1286 条
- 12 台并发探测 7.0s；5 台进入冷却后 2.9s

## 6. 已知局限

- 看板内不区分服务器（归到 `_codex_session`），要拆分看 `ccr report`。
- `$` 是按 `model-pricing.json` 折算的 token 成本，**不等于中转站账单**。
- 只支持 Linux + 公钥免密（`BatchMode=yes`）。
- 依赖 agent 日志在默认位置（`~/.codex/sessions`、`~/.claude/projects`）。
- 时间戳与本地时区跨日时会话归属可能「差一天」，属预期。
